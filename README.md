# 断字词典调试器（Hyphen Dictionary）

离线的断字词典调试页面，原生 TypeScript 实现，由 Docker Compose 的 **hyphen** 服务静态提供。
针对 Knuth-Liang 风格断字规则中「同一字符间隙多条规则互相覆盖、最终奇偶决策难以解释」的问题，
本工具逐间隙展示：

- **最终分值**：加边界符（`.word.`）后用模式 trie 匹配，每个间隙取所有命中模式数字的**最大值**；
- **贡献来源**：哪些模式给出了该最大值（同分并列时全部保留、去重、排序）；显式写出的 `0` 也是一种命中——最终分值为 0 时会把写 `0` 的模式列为来源，而不是笼统地说"无命中"；
- **排除原因**：偶数显式禁止、不满足左/右最少保留字母数等，逐间隙给出人类可读说明；
- **例外覆盖**：例外词的显式断点（`-` 标注）覆盖模式的分值与奇偶结果，但**仍须满足左/右最少保留字母数**；越过限制的标注断点一律标为不可断并说明原因。

修改词典后自动重新计算；**导出 JSON 与页面高亮取自同一份 `WordResult[]`，不做二次计算**，因此逐间隙严格一致。

## 规则规格

- **模式**：每行一条，0～1000 条。小写 ASCII 字母连续排列，整体（含数字）首尾各可带至多一个边界符 `.`（边界符必须在最前/最后，数字只能在边界符内侧的间隙）；
  每个字符间隙（含首尾）至多一位 `0~9` 数字——同一间隙写两位数字（含 `00`、`01`）属于语法错误，导入即拒绝。
  - 数字标记它在模式串中占据的物理间隙：`he2l` 的 2 在 `e|l` 之间；`5abc` 在首字母前间隙；`abc8` 在末字母后间隙；`.0abc` 的 0 在边界符与首字母之间。
  - 匹配在加边界符的词 `.word.` 上进行；`.` 只能与词首/尾的边界符对齐。
  - 奇数允许断开，偶数显式禁止（若有更大的偶数覆盖了奇数，则该间隙禁止），0 表示无意见（但与"无命中"区分：写 0 的模式会出现在来源中）。
- **例外词**：每行一个，用 `-` 标注显式断点，如 `as-so-ciate`；没有 `-` 的词条用于压制模式断点。
  显式断点可覆盖模式分值与奇偶结果，但左/右最少保留字母数对例外同样生效（判定在分析阶段进行，调整最少保留数后结果立即重算）。
- **左/右最少保留字母数**：可断位置左、右至少保留的字母数，对模式断点与例外断点一视同仁。
- **输入词**：最多 2000 个，每个长度 ≤ 40，小写 ASCII，每行一个。

## 开发

```bash
npm install
npm test       # Vitest：trie 与「朴素逐模式扫描」预言机对拍
npm run build  # tsc 类型检查 + vite 生产构建到 dist/
npm run dev    # 本地开发服务器
```

测试覆盖：

- trie 与朴素逐模式扫描的逐间隙对拍（分值 + 贡献来源），含 100 组随机词典对拍；
- 重叠规则在同一间隙取最大权重、偶数禁止、同分并列来源；
- 同间隙两位数字（含 `00`/`01`）与点号错位（如 `a1.b`）在导入时被拒绝；显式 0 的来源可见；
- 边界符 `.` 仅对齐词首/词尾、首尾数字的间隙定位；
- 左右最少保留字母数的排除原因；
- 例外词显式断点覆盖分值与奇偶结果（含对奇数结果的压制、冲突例外报错），但越界断点同样被左右最少保留数压下；
- 无命中 / 无断点词；
- 导出 JSON 的 `allowed` 间隙与 `breaks`、高亮完全一致（含越界例外断点四端一致不放行）。

## 用 Compose 的 hyphen 服务提供（离线）

镜像构建阶段先运行 `npm test` 与 `npm run build`，运行阶段仅为 nginx 静态托管，无运行时外部依赖：

```bash
docker compose up -d --build
# 打开 http://localhost:8080
```
